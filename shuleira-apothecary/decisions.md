# 判断の記録（decisions.md）

work委譲用指示書 v1.1 §06 に基づき、「自分で決めてよいもの」はここに決定と理由を記録し、
「保留にするもの」は暫定対応とあわせてここに記録する。

## 決定事項

### D01. 配置場所を一時的にHunyuan3D-2リポジトリのサブフォルダにした
- **決めたこと**: 専用リポジトリ `eiji-lab/shuleira-apothecary` を新規作成しようとしたが、
  GitHub App連携に `Resource not accessible by integration`（リポジトリ作成権限なし）で失敗。
  作者の判断で、一旦 `Hunyuan3D-2` リポジトリのサブフォルダ `shuleira-apothecary/` に
  自己完結した状態で配置し、既存ブランチ `claude/new-session-h6ewip` 上で開発を続行する。
- **理由**: 作者が翌日から長期間連絡不可のため、リポジトリ作成待ちで停止しないこと優先。
  ディレクトリを自己完結（独自 package.json / node_modules は配下限定）にしておけば、
  後日 `git subtree split` 等で専用リポジトリへ移行するのは容易。
- **帰還後にやること**: `eiji-lab/shuleira-apothecary` を作成し、このフォルダの履歴を移す。

### D02. 技術スタック
- **決めたこと**: TypeScript + Vite（devDependencyとしてのみ使用）。テストは Vitest。
- **理由**: 指示書の制約「CDN依存を作らない。オフラインで完全に動作すること」は
  *本番ビルド後の成果物* に対する制約と解釈した。Viteはビルド時ツールであり、
  `vite build` の出力（`dist/`）は外部リクエストを一切行わない静的HTML/JS/CSSになる。
  素のTSファイルをブラウザに読ませる方式より、バンドル・型チェック・テストの土台が
  短期間で安定して組める点を優先した。

### D03. データの読み込み方式
- **決めたこと**: `materials.json` 等はすべて `src/data/` 配下に置き、
  TypeScript側から `import data from './data/materials.json'` で静的import する。
  実行時の `fetch` は行わない（＝オフライン時にネットワークエラーになる経路を作らない）。
- **理由**: 指示書「コード内に数値・文言をハードコードしないこと」は満たしつつ、
  「CDN依存を作らない。オフラインで完全に動作する」を両立する最も単純な方法。

### D04. localStorage 保存モジュールの分離
- **決めたこと**: `src/state/storage.ts` に読み書きを隔離し、
  ゲーム側は `SaveStore` インターフェース越しにしかアクセスしない。
- **理由**: 指示書「保存処理は薄いモジュールに隔離し、差し替え可能にすること」に対応。
  将来的にIndexedDBや別ストレージに差し替える場合、このファイルだけ差し替えれば済む。

### D05. JSONスキーマ設計（第1段階）
- **薬効軸**: `鎮静/覚醒/鎮痛/解毒/遮断/保持/解熱/浮遊`。強度は 1〜3（＋〜＋＋＋に対応）。
- **副作用軸**: `依存/毒性/鈍麻/混濁/発熱/腐食`。同じく強度 1〜3。
- **特殊素材**の扱い:
  - 04谷水・05霧雫は「希釈用」。効果軸を持たず、`effects: []`。
  - 11濁茸は「他の全薬効を+1段階引き上げる」ため `amplifiesAllEffectsBy: 1` という
    専用フィールドを追加（他の素材にはない）。
  - 21神樹落葉は「全軸+1」のため `effects` に8軸すべて strength:1 を明示的に列挙。
- **在庫層** (`supplyTier`): `常時在庫 / 配給 / 交易入荷 / 密輸` の4種。
  素材一覧の見出し（渓谷産／煙草関連／帝国産／他国産／密輸品）から機械的に対応させた。
- **試作範囲外データも全件残す**: `inPrototypeScope: boolean` を客・症例・助言役の各エントリに
  付与し、指示書「データには全10種・全12症例を入れておくこと」を満たす。表示・出現の
  ON/OFFはこのフラグで制御する（後から有効化できる設計）。

### D06. 例外組み合わせE03（カトレア塩）の扱い
- **決めたこと**: `combos.json` にE03を「予約済み・未実装」として残す
  （`status: "reserved"`, `active: false`）。カトレア塩は現行22素材に含まれないため
  発火しない。素材追加の判断自体は「保留」（下記P03参照）。
- **理由**: 指示書は素材の追加・削除を「保留にするもの」に明記。E03の番号を欠番にせず
  ドキュメントの番号体系をそのまま保持した。

## 保留事項（暫定対応込み）

### P01. 新人ちゃん（仮）の名前・設定
- **内容**: 助言役4人目「新人ちゃん（仮）」の名前・詳細設定が未定。
- **暫定対応**: `advisors.json` に `id: "shinjin"`, `name: "（未定）"`,
  `inPrototypeScope: false` として構造だけ用意。台詞データも未着手のため空配列。
  試作の実装範囲（助言役2名: シュレイラ/ラプラス）には含めない。
- **判断が必要な理由**: キャラクターの新規設定は「保留にするもの」に明記されている。

### P02. 台の傷みの具体的な閾値
- **内容**: 「腐食の副作用がある素材（蝕鱗・灰死粉）を使うと蓄積」「限界に達すると
  その日使用不可」とあるが、具体的な閾値（何回で焦げるか）は未確定。
- **暫定対応**: `progression.json` に `tableDamageThreshold: 3`
  （腐食+1の素材を3回使用、または腐食+2を2回相当で焦げる想定の
  ダメージ蓄積式 `sum(腐食strength) >= 3` で使用不可）を仮設定。
  バランス検証（第4段階）の結果次第で調整可能な数値としてJSON化した。
- **判断が必要な理由**: 数値バランスは「検証結果に基づく限り」自分で決めてよいとされているため
  暫定値を確定値に近い形で設定しつつ、キャラクター/世界観に関わらない純粋な数値として
  このまま実装を進める（＝止まらない）。分類上は「決定事項」寄りだがv1時点の根拠が
  薄いためここに記録。

### P03. オルガの声かけ条件の詳細
- **内容**: 「プレイヤーの状態が中度以上の時にのみ発生」以上の詳細条件が未確定
  （毎回か、確率か、1日1回か）。
- **暫定対応**: `symptoms`/`progression` 側で「1日1回、中度以上に最初に達したタイミングで発火」
  とし、dialogue.json内のオルガの当該台詞に `trigger: "onFirstModerateOrWorsePerDay"` を付与。
  指示書の「毎回出すと安っぽくなる」という注記を優先した頻度設計。
- **判断が必要な理由**: 演出頻度は世界観の受け取られ方に直結するため、キャラクター表現に
  関わる判断として保留カテゴリに位置づける。

### P04. BGMの有無
- **内容**: 環境音のみで足りる可能性がある、と記載されているが未確定。
- **暫定対応**: 試作では実装しない（環境音・BGMともになし）。音量スライダー／ミュートは
  将来のSE/BGM追加に備えて先に実装する（指示書§02で必須項目のため）。
- **判断が必要な理由**: 世界観の音響表現に関わるため。

### P05. 在庫のリセット方式（日次 or 通し）
- **内容**: 在庫を1日単位でリセットするか、通しで管理するかが未確定。
- **暫定対応**: 「通しで管理」を採用（在庫は日をまたいで持ち越す）。理由: 客の支払いが
  翌日在庫に加算される仕様（§03確定事項）と整合するのは通し管理であり、
  日次リセットだと「置いていった物が翌日の在庫になる」という中核ループと矛盾するため。
  ゲームデザイン上の整合性から選んだが、世界観そのものへの影響はないため本来は
  「決定事項」寄り。念のためここに残し、報告書で最優先確認事項にはしない。
- **判断が必要な理由**: 経済/資源設計の根幹に関わり、後から変更するとバランス調整が
  やり直しになるため、作者確認を推奨する項目として記録。

### P06. カトレア塩を素材に加えるか
- **内容**: 現行22種構成では未採用。E03が空き番号のまま。
- **暫定対応**: 追加しない。E03は「予約済み・未実装」のまま試作を完成させる。
- **判断が必要な理由**: 素材の追加は「保留にするもの」に明記。

### P07. ロゥエンの席が空いた後、何が起きるか／言及の有無
- **内容**: 根治後の枠に誰が入るか、ダンが来なくなった後に言及があるか、いずれも未確定。
- **暫定対応**: 試作範囲（客5種）にロゥエン・ダンは含まないため、試作では影響なし。
  ただし `customers.json` の当該データには `seatVacatesOnCure: true`
  （ロゥエン）を構造だけ用意し、本実装時にすぐ組み込めるようにした。
- **判断が必要な理由**: 世界観の核心（§10「抑えることで保っている国」）に直結する演出判断。
